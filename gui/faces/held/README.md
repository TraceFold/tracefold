## The one discipline this face exists to hold

A held candidate carries a digest and a path the same shape a settled row does, drawn with the same `receipt-row.mjs` grid `faces/ledger` draws its own held half with. The one thing that must never happen is a reader coming away believing anything on this screen has been checked, sealed, or committed. That is held structurally, not by a sentence someone could stop reading:

- `toRecord()` sets `holes.seal` **unconditionally**, on every record, before anything else is computed.
- `parts/src/receipt-row.mjs`'s own seal-cell logic (shared with faces/ledger) draws a hole whenever `record.holes.seal` is set, never a value -- there is no code path in this face that could ever produce a `data-state="value"` seal cell.
- `tools/gate.mjs` adds an eleventh source check (`no-unconditional-seal`, pattern-matching a seal cell drawn as anything but a hole) and a **fourth drawn-tree check** (`seal-column-is-always-a-hole`) beyond the ten+three faces/ledger's own gate carries, and both refuse to pass on an empty population.
- `tools/shoot.mjs` adds a `sealValues` reading (count of seal cells not drawn as a hole) to the four negative-truth readings this project already shares across faces/ledger and faces/notice.
- The claims section states, in the open, that nothing on the screen is checked (`HELD_MESSAGES.NOT_A_RECEIPT`), in the legend once and again inside the claims heading.

**Negative control performed, not just planted**: `toRecord`'s seal-hole assignment was removed for real (`held.mjs`, `holes = {}`), and all three independent detectors fired red -- `node --test` (2 tests: the gate suite and the dedicated behavioural test), *and* `tools/shoot.mjs`'s live-renderer probe (`sealValues=3` on the `held` fixture, was 0). The file was restored from a byte-for-byte backup and `cmp` confirmed identical restore; a second `node --test`/`shoot.mjs` pass confirmed green again (68/68, `sealValues=0` on all 7 captures). This is a stronger result than faces/ledger's own AC-F1 negative control recorded (its screenshot-clause probe did *not* go red on that break, an honest gap that README states) -- here the DOM-level test and the pixel-probe both catch the same break, because `sealValues` reads `data-state` directly rather than inferring anything from geometry.

## The readiness ladder (retrofit round 4)

The four acts were always here, one gutter per row, each of them either live or dimmed. What the screen never said was **why**. It says it now, above the list, one container per declared gate: the gate's own answer first, the act that gate governs inside the same container, and the reason an unavailable act is unavailable **beside the disabled control**, at the size the rest of the screen is read at.

The gates are declared in `declaration.mjs` (`GATES`), one per declared act, and the ladder ends at the terminal one because that is where the eye stops:

| gate | act | answered from | on this screen |
|---|---|---|---|
| raised to a person | `escalate` | the declaration's own withholding | **shut** -- the request body was never read out of the crate that serves it |
| an inverse held | `undo` | `parts/src/reversibility.mjs`, per candidate | **shut** -- nothing here has happened yet, so no inverse is held |
| withdrawn instead | `cancel` | the acts this face sends + the chosen row's identity | **open** once a candidate is chosen |
| committed | `commit` | the acts this face sends + the chosen row's identity | **open** once a candidate is chosen |

Three answers, and the two absences are kept apart: `shut` is a condition this window read and found unmet, `unknown` is one it could not read at all. A read that did not answer draws **four unknown gates and no open one** -- a gate this window could not read is never drawn as a passed one, which is the property `test/held.test.mjs` pins with a refused read.

The inverse gate is the one a forward-only tool cannot draw at all, and it is drawn here as what it honestly is: no inverse is held, computed per candidate rather than assumed, and with no path to `open` on a screen where nothing has happened.

## Round 5 (Owner #348 / #349): the second way to reach an act, the icon floor, and the type

**The menu.** Every interactive row, every act control and every gate answers a right-click with a menu, and what the menu offers is not a second set of verbs: it is the row's own gutter -- all four declared acts, each drawn whether or not it sends -- answered by the ladder's own gates for the candidate the pointer was on, plus `copy value` for the cell it was over. One declaration, one rule, three surfaces. A menu item carries `data-act`, and carries `data-target` only where its gate is open, so pressing one travels the identical path a gutter button travels: the same queue, the same per-candidate in-flight lock, the same log. There is no second sender in the file, and `test/held.test.mjs` pins it by sending a commit from the menu, then re-opening the menu while that commit is still out and finding the same act offered dead with the same in-flight reason the row and the gate give.

It is drawn **in flow**, under the row or under the gate it was opened on, not floating at the pointer. Nothing this face draws may leave the flow (`nothing-out-of-flow`, held at zero over the source), because the defect the row grammar was rebuilt around was an absolutely positioned note drawn on top of the row below it. The cost is measured and stated below: the row that owns an open menu goes from a 164px pitch to 293px at 720px wide, and returns to 164px the moment the menu is dismissed.

Dismissal is pinned three ways -- Escape, a press away, and the fact that the menu is drawn from state rather than appended to a document, so a repaint cannot leave one behind and a second right-click replaces the first rather than stacking on it. `tools/gate.mjs` holds `one-menu-at-most` over every drawn state and refuses to pass on a screen nobody right-clicked.

`copy value` takes what the cell **holds**, not what the row drew -- the time cell draws a declared cut and carries the whole timestamp, and the menu offers the whole one. It states whether it worked (`data-copied` / `data-copy-failed`, the same two attributes the shell's own copy control sets) rather than looking the same either way, and a window with no reachable clipboard says so. A cell holding nothing offers the copy dead with the reason instead of dropping it.

**The icon floor (#348 (3)).** `parts/test/glyph-sheet.test.mjs` named two call sites in this file, both at 12--15px against a 16px floor: the control toggle's fold mark and the ladder's own act control. Both now name the floor rather than a number (`P.minReadable` / `P.minAct`, imported through the binding), and the band's four marks were changed from a literal `16` to the same name. The act control takes the higher floor because it sits on the thing a hand is aimed at.

**The type (#348 (4)).** Three weights, chosen by what a run of text is: `figure` (600, matching the shared figure rule so a count in this face's type and a count in a shared container are one weight), `name` (500), `body` (400). No call site spells a weight and `no-raw-weight` holds that at zero. Prose breaks in one place too: `overflow-wrap: anywhere` -- which lets an ordinary word come apart at whatever character a narrow line ends on -- is gone from this face and held at zero by `no-mid-word-break`, replaced by `break-word` (a word breaks only where it cannot fit a line of its own) plus `text-wrap: pretty` against a last line holding one character. Both readings are taken off the renderer's own line boxes in `tools/shoot.mjs`: **0 orphan lines and 0 break-anywhere paragraphs on all 13 captures**.

**What is mechanical (#348 (5)).** Four new source greps in this face's own gate, each fired red on planted source before it was trusted, and two of them fired red on the shipped file first: `no-face-motion` (no `transition:` and no bare `ms` -- there is one motion route and a face is not it), `no-raw-corner` (a radius is one of the three declared tiers, named), `no-raw-weight`, `no-mid-word-break`.

## The three load-bearing properties

**Nothing here wears a receipt's face.** Every seal cell on every row is a declared hole, unconditionally -- the one property this face exists to hold, checked four independent ways (source gate, drawn-tree gate, dedicated behavioural test, live-renderer `sealValues` reading) and negative-controlled for real (see above).

**A list that could not be read is never an empty one.** Same fail-closed discipline faces/ledger holds: `failed`/`refused`/`absent` reads are drawn `data-state="unread"` with the outcome named, never given the empty-list's words.

**An act does not rewrite the row it targeted.** Committing or cancelling a candidate is answered by re-reading the list, never by this face editing the row's own drawn markup -- verified by drawing before/after and asserting the committed id is absent from the second render while an unrelated id survives.

## The vertical four-button gutter is now indefensible, and here is the arithmetic

Stated plainly, because this face is the worst density on the tree and this round made the case against the gutter rather than improving it.

One candidate is **one line of text** and costs **164px** of screen. 156px of that is the gutter: four buttons at 36px with three 4px gaps, stacked beside a 44px row. At 720px wide the screen shows **6.1 rows per 1,000px**; with the 594px head, a 1400px window holds **about 4.9 candidates**. The gutter also now clips two of its four labels (above). Both halves of the failure come from the same decision -- four acts, always drawn, stacked vertically in a fixed 84px track.

The shape this round argues for: **the gutter carries the row's terminal act only, and the other three move to the menu that now exists.** The property `req/768 AC-4` protects -- that a withheld act must never be indistinguishable from an act that was never offered -- is preserved by the menu rather than by the gutter, because the menu draws all four from the same declaration, each with its gate's answer and its reason, and it is reachable on every row. A one-button gutter is 36px, so the row block falls to about **46px** and the same 1400px window holds roughly **17 candidates** instead of 4.9. The 84px track then comfortably fits one 20px mark and one label, which also closes the clipping.

This is not implemented here. `GUTTER_WIDTH` and `actGutter()` are `parts/src/receipt-row.mjs`, which this lane does not own, and cutting the offered set from four to one is a change to what `req/768 AC-4` was scored against -- it belongs to whoever owns both.
